# Ghost (formerly Vault Sorter): Destiny 2 vault sorting on top of DIM

**Current plan: `GHOST_PLAN.md`** (visual overhaul + GitHub Pages copy with Bungie sign-in). Its Security section is a release blocker for every step; see *Security* below for what is in place.

## Goal (in the user's words, condensed)
Help sort a Destiny 2 vault. Read all the information for each item, and tag and add notes to items so they show up in **DIM (Destiny Item Manager)**. Auto-sort and view items by notes, tags, rarity, element, archetype, frame, stats, source, power, tier and perks. Show **several sort queries at once**. **Highlight on each item why it matched** a query. Show a **rating per weapon**: since 2026-11-17 Ghost's own (see *Ratings*), because light.gg has no API, blocks automated access and its data isn't ours to redistribute.

## How it works
- **Input:** DIM's own spreadsheet export (DIM → Settings → Spreadsheets → Weapons / Armor CSV). The claude.ai artifact build has no Bungie API code; the hosted build (GitHub Pages, GHOST_PLAN track A) will add Bungie sign-in and keep the CSV drop for tags/notes.
- **Output to DIM:** a CSV with `Name,Hash,Id,Tag,Notes` for changed items only, loaded through DIM → Settings → Spreadsheets → *Import tags/notes*. This is the **only** write path into DIM: DIM Sync's API keys are issued by the DIM team, so outside apps can't use it. Importer source: `reference/dim-spreadsheets.ts` → `importTagsNotesFromCsv`.
  - It needs the columns `Id`, `Hash`, `Tag`, `Notes`. An empty Tag or Notes **clears** that field in DIM, which is why only changed rows are exported, each carrying its full current tag and notes.
  - Valid tags: `favorite keep junk infuse archive`. DIM caps notes at 1024 characters.
- **Ratings:** Ghost's own PvE/PvP scores from the DIM community wish list, Aegis's Endgame Analysis and Ghost's perk ratings (defaults + personal). See *Ratings* below.

## DIM CSV format (from DIM source `generateCSVExportData` + `organizer/Columns.tsx`)
Column order: `Name, Hash, Id, Tag, Rarity, Tier, Type, Source, Equippable, Category, Element, Ammo, Power, Energy Capacity, Archetype, Tertiary Stat, Tuning Stat, Masterwork Type, Masterwork Tier, Owner, Locked, Equipped, Featured, Holofoil, Year, Season, Event, <stats>, <stat> (Base)…, Crafted, Crafted Level, Kill Tracker, Foundry, Seasonal Mod, Loadouts, Notes, Perks 0..N`.
- `Rarity` = Exotic/Legendary…; `Tier` = gear tier (1–5, from Edge of Fate). These are different things.
- `Archetype` = **frame** for weapons (e.g. "Precision Frame") and **armor archetype** for armor (e.g. "Bulwark").
- Weapon stats: `Recoil, AA, Impact, Range, Zoom, Blast Radius, Velocity, Stability, ROF, Reload, Mag, Handling, Charge Time, Draw Time, Accuracy, …`. Armor 3.0 stats: `Weapons, Health, Class, Grenade, Super, Melee, Total`.
- `Perks N`: a **flat list**. Socket boundaries are lost. Order is intrinsic, then perk sockets (every plug option; the equipped one ends in `*`), then mods/masterwork/shader. Kill trackers appear as a single name.
- PapaParse `escapeFormulae`: values starting with `= + - @` get a leading `'`, which `unesc()` strips.

## Query language (in `core.js`, close to DIM's)
Terms placed side by side are ANDed, `or` separates alternatives, `-term` or `not:` negates, `"quotes"` group words. Keys: `is:` (weapon armor exotic… solar… crafted locked vault dupe tagged hasnotes pending rated unrated masterwork holofoil, or any type such as `is:handcannon`), `tag: notes: name: rarity: element: type: frame:/archetype: source: ammo: class: slot: owner: tertiary: tuning: mw: event: foundry: perk: perksel: exactperk:`. Numeric keys take `= > >= < <=`: `power tier rating pve pvp level kills season year energy mwtier total count`, plus `stat:<name><op>N` / `basestat:`. `sort:<key>` inside the query overrides the pane's sort dropdown.
Also: `breaker:` (`shieldpiercing|antibarrier`, `disruption|overload`, `stagger|unstoppable`, `any`, `none`), `is:breaker`, `is:shieldpiercing/antibarrier/disruption/overload/stagger/unstoppable` (hit key `breaker`); `desc:`/`clarity:` searches Clarity + Compendium text of the item's perks (hit keys `perk:<name>`). Sort keys `ammo` (Primary→Special→Heavy), `breaker`, `crafted`; group keys `ammo`, `breaker`, `crafted`.
`runQuery` returns `Map(itemId → Set(hitKeys))`. Hit keys (`type`, `frame`, `perk:<name>`, `stat:<name>`, `rating`, …) drive the per-pane highlight on cards and in the item drawer. **Every new filter must return the field keys it matched**, or highlighting breaks.

## Ratings (Ghost's own, 2026-11-17; user decision)
light.gg was dropped (no API, blocks automated access, not ours to redistribute; Clarity has no ratings). Every weapon gets a **PvE and a PvP score (0–100)**; `it.rating` = their average (or the one that exists). `Core.rateGhost(it, defs, RT, UR, cmap)` fills `it.rating/pve/pvp` (so sorting, Clean up ranking, `rating:`/`pve:`/`pvp:` queries and the Compare row work unchanged), `it.perkRel[name] = {e, p, rel}` (perk tiers for chips; `rel ≥ 85` = gold outline) and `it.why` (the parts, for the item panel). The old light.gg `prepRatings`/`rateItem` stay in core only for their tests.
- **Parts and weights** (default perks 50 / wish 25 / Aegis 25, adjustable per profile; a missing part is left out and the rest rescaled; Aegis is PvE only, so PvP = perks + wish list):
  - **Perk & combo ratings = the best possible roll (user rule 2026-11-17):** tiers S A B C D E F = 100 85 70 55 40 25 10. `perkPart` tries every selection of one perk per column (`Core.sockets` cols) from all rolled options, equipped or not (capped at 20,000 selections, then top 4 per column), and keeps the highest score: chosen perk tier per column (barrel/mag ×1, traits ×2, origin ×0.5) plus the best rated combo among the chosen perks (×2); ties keep the equipped perks. It returns the picks (`cols[].pick`, `switched` = differs from equipped), the combo used and the equipped roll's own score; the panel shows "Best roll … Combo: A + B" and "select it · equipped: X".
  - **DIM wish list:** per listed roll each perk set scores 1 (equipped perk in it), 0.4 (only an unselected option), 0; trait sets count double; best roll per mode (rolls tagged PvE/PvP, untagged = both). A trash roll fully matched by equipped perks sets that mode to 0. `item=-69420` rolls apply to every weapon.
  - **Aegis's Endgame Analysis:** his weapon tier (PvE). Shown everywhere as "Tier X · Aegis's Endgame Analysis" (credit required; also on About).
- **Defaults (`pk`, `cb` in `data/ratings.json`), data-derived only, never invented:** PvE = Aegis's tier from his *Perks* / *Origin Traits* tabs where he lists the perk; otherwise (and for PvP) the share of curated wish lists that pick the perk among weapons that can roll it and have curated rolls for that mode (≥50% S, ≥30% A, ≥18% B, ≥8% C, >0 D, 0 E; fewer than 4 such weapons = no default). Combos = trait pairs listed together on ≥4 weapons (≥25% of the weapons that can roll both). Each default carries its source text, shown on the ratings page. Clarity / Compendium text is shown with each perk (tap its name) but doesn't set tiers.
- **Personal ratings:** `UR = {p: {normName: {e, p}}, c: {comboKey: {a, b, e, p}}, w: {perks, wish, aegis}}` per profile in localStorage `PK('perkRatings')` and db `PP('config/perkRatings')`; `'x'` = unrated on purpose. Validated by `Core.prepUserRatings` (key patterns, tier allowlist, weights 0–100, caps). Deleted with the profile.
- **Table shape / validation:** see the comment above `Core.prepGhostRatings` (wish list: perk-name and note dictionaries, per weapon hash `[flags, noteIdx, [[perkIdx…]…]]`; Aegis: per hash `[tier, tabIdx, noteIdx, alts]`). The tool groups consecutive same-note lines into per-position perk sets when the block is an exact Cartesian product (8457 of 8923 blocks), else keeps the lines apart; perk hashes become names (enhanced = same name), so CSV and API items both match; notes lose their tag list and are cut to 180 chars. The page re-validates the table at load; everything from it is rendered with `esc()`.
- **Sources:** voltron.txt from github.com/48klocs/dim-wish-list-sources (MIT; credit 48klocs, u/-seudonym- and u/zman2100's ShardItKeepIt community rolls, and the curators named in its description, stored in `meta.credits`). Aegis's **Destiny 2: Endgame Analysis** sheet `1JM-0SlxVDAi-C6rGVlLxa-J1WGewEeL8Qvq4htWZHhY` (gviz CSV per tab; weapon tabs map to weapon types, rows to hashes by name; "Name + second line" rows become "Other versions"). The user reports Aegis approved this use. The sheet ID `1i1KUwgV…` in the 2026-11-17 brief is Court's infographics sheet, not Aegis's.
- **Compare:** the rating row shows PvE · PvP · Total in text colour plus a letter-grade stamp (`Core.ratingGrade`: nearest tier score), because green in Compare means "best stat" (user decision 2026-11-18). Elsewhere ratings keep `rateColor` (green / yellow / red).
- **UI:** item panel "Rating" section (PvE / PvP / Rating boxes; collapsible Perk & combo ratings per column, the DIM wish list's best roll with matched perks and its note, the Aegis tier + note + credit; "Adjust perk ratings & weights"). **Perk ratings** view (`#ratings`, `renderRatings`, opened from the desktop rail button `#bRatings` and the phone ⋯ menu `#mRatings`, not a nav tab): weight sliders, Perks / Combos tabs, perks grouped by column (barrel, magazine, trait, origin; armor archetypes), filters for weapon/armor, weapon type, element-specific and "only my changes"; each row has PvE/PvP tier selects (Default (X) / S…F / Unrated), the default's source and Reset; best rated first. Changes re-rate every item (`rerate()`).
- Refresh: `npm run ratings` (or `node tools/build-ratings.mjs` to reuse the cache), then rebuild. After a game update run `npm run defs` first so new weapons and perks exist.

## Reference data (`data/defs.json`, ~3 MB, built by `tools/build-defs.mjs`)
- **Breakers (every weapon has one since Update 9.7.0):** Bungie stores each weapon's breaker as a sandbox perk named `[Shield-Piercing] Barrier` / `[Disruption] Overload` / `[Stagger] Unstoppable` on its intrinsic (frame) plug. `build-defs.mjs` reads it per weapon hash into `wb` (weapon perks → initial intrinsic plug → first plug of the intrinsic socket's plug set → legacy `breakerType` → another copy with the same name): 2208/2208 weapons in manifest 245114. `fb` maps intrinsic names to breakers where every weapon with that intrinsic agrees. `Core.applyDefs`: `wb[hash]` → `fb[frame]` → `Core.archetypeBreaker` (Bungie's 9.7.0 archetype table, only for weapons newer than the data snapshot). `it.breakerSrc` = 'bungie' | 'rule'. Checked against light.gg (Dead Man's Tale = Shield Piercing, Witherhoard = Disruption); the archetype table agrees with Bungie's data on every legendary. Don't guess exotics from names or the Compendium.
- **Armor sets:** `as` (armor hash → index into `sets`), `sets[i] = {n, p:[{c: pieces, n, d, i}]}` from `DestinyEquipableItemSetDefinition` + sandbox perks. `it.set`; query `set:` / `is:setbonus`; sort/group `set`.
- **Plugs:** `pi[normName] = [iconPath, socketType, bungieDescription, hash]`; `pw` / `pa` hold weapon-side / armor-side entries for names used by both (e.g. Demolitionist = weapon trait and armor archetype). Always look plugs up with `Core.plugOf(name, defs, kind)`, which also refuses armor-only types on weapons and vice versa. Socket types drive the game-style layout (`Core.sockets`): `i` intrinsic, `r` armor archetype, `b` barrel-like, `m` magazine-like, `t` trait, `o` origin, `w` weapon mod, `k` masterwork, `c` catalyst, `a` armor mod. DIM's flat perk list is split into columns when the type changes or a second equipped perk appears.
- **Clarity** (`cl[normName] = {h, ty, e?}`): rendered to HTML keeping Clarity's own classes (`cl-pve`, `cl-solar`, `cl-enhancedArrow`…), styled in app.html.
- **Destiny Data Compendium** (`dc[normName] = {h, s}` or `{x: exoticKey, s}`, `dcx` exotic weapon docs, `dset` set bonuses, `dcs` style list): parsed from each tab's public `htmlview` page by `tools/compendium-html.mjs`, keeping the sheet's colors/bold/italics as `<span class=dN>` with the styles in `dcs`. Saved under `data/raw/compendium-html/`. Gviz CSVs drop formatting, and xlsx export is disabled by the owner.
- **Subclasses:** `sub[class][element] = {n, h, i, s: {super, classAbility, movement, melee, grenade, aspects, fragments, transcendence}}` from plug categories `warlock.<el>.*` / `shared.<el>.*` (stasis aspects = `totems`, fragments = `trinkets`, Prismatic = `prism`). Shown in the Subclasses viewer (Warlock first) with Bungie + Clarity + Compendium text and light.gg links.
- **Icons:** elements, ammo, breakers are data URIs. Every other icon (perks, mods, intrinsics, set bonuses, subclass abilities) comes from one sprite sheet, `dist/icons.webp` (48px cells, 48 columns, ~2.3 MB), because claude.ai blocks images from bungie.net. Pipeline: `tools/build-defs.mjs` → `node tools/fetch-icons.mjs` (downloads to `data/raw/icons/b/`, writes `list.json`) → `python tools/build-sprite.py` (Pillow, writes `data/sprite.webp`; `tools/build-sprite.ps1` is a no-install PNG fallback, ~5 MB) → `build.py` swaps icon paths for sprite indices and copies the sheet to `dist/icons.webp` (or `.png`). **Publish the sheet alongside the page** (`files: {"icons.webp": "dist/icons.webp"}`).
- **Cosmetics hidden:** `cos` lists normalized shader/ornament/Combat Flair/tracker/memento names; `applyDefs` marks those perks junk so they never show.
- **Sockets:** `Core.sockets` returns intrinsic, perk columns, exotic perks, mods, `mw` (masterwork) and `catalyst` separately.
- **Keyword search:** free text and `desc:` match Bungie + Clarity + Compendium text of perks, mods, set bonuses and exotic weapon notes (`Core.descHits`), with word-form matching (`Core.keywordRe`: freeze→frozen, ignition→ignite…).
- **Card preview** shows only name, rarity, tier, power, element, ammo, weapon or armor type, archetype/frame, intrinsic (+exotic perks), breaker, crafted, tag, notes. Anything else (perks, stats, source, set, rating…) appears only when the pane's search hits it (highlighted) or it is the sort key.
- **Clarity / Data Compendium have no perk ratings.** light.gg returned **403** to plain `curl` (2026-11-14); ratings now come from Ghost's own system (*Ratings*).
- **Sort/group menus follow the query:** options are rebuilt from each pane's results (weapon-only vs armor-only keys, stats present); the current choice stays listed with "(not in results)".

## Views
Header tabs switch views (`setView`): **Vault** (the query panes), **Clean up**, **Compare**, **Builds**, **Subclasses**; **Perk ratings** (`ratings`) opens from the rail / ⋯ menu. Non-vault views are fixed overlays placed under the header (`placeViews`).

### Builds (build maker, 2026-11-17)
State `BLD = {list, cur}` per profile in localStorage `PK('builds')` and db `PP('config/builds')`; every stored build is rebuilt by `validBuild()` (ids, hashes, item ids, string lengths). A build holds refs only: `cls`, `el`, `sub` (plug hashes: super, classAbility, movement, melee, grenade, aspects[2], fragments[≤ aspect slots]), `w`/`a` (`{id, hash, name}` per slot), `mods` (names, ≤3 per armor slot), `notes`, and `subMem`/`aMem` so switching class/element and back restores choices. Refs keep hash + name for a later theorycrafting mode (items the player doesn't own; decided 2026-11-17: vault only for now).
- **Interactions = curated data only (2026-11-17, user decision):** keyword matching misread conditions ("if running Healing Rift") and missed created things (Child of the Old Gods → Void Soul → Briarbinds), so every piece is read and curated into `data/interactions/` (schema and rules: `data/interactions/README.md`). `tools/interactions/sources.mjs` writes source packets (Bungie + Clarity + Compendium text per piece) to `data/interactions/src/`; curators (Claude + subagents) write `pieces/*.json` and glossary terms (`glossary.json` + `glossary/*.json`, our own compendium of verbs/objects built from the Compendium's element glossaries); `tools/interactions/check.js` (also run by `npm test`) fails on unknown ids/terms/pieces and on any quote that isn't in the source text. `build.py` bundles it as `window.VS_IX` (`{t, p, pending}`).
  - Engine `Core.ixEval(pieces, ix, defs)`: effects `creates/applies/grants` provide a term, `uses/modifies/consumes` take it, `counts` makes one term count as another (Void Soul → grenade); conditions (`slot`/`piece`/`item`/`has`/`weapon`/`any`) are checked against the build; failed ones are listed as "Not active in this build" with the reason. Chosen abilities implicitly provide their ability term (+ family rift/barricade/dodge, + `<element>ability`) and spend their own energy. Pieces with packets but no record are "Not reviewed yet"; nothing uncurated is ever claimed.
  - UI (layout "A2", chosen by the user 2026-11-17 from prototypes): tabs Overview / By piece / Not active / Missing (`IXTAB`). Overview = kind sections (Buffs, Debuffs, Creations, Ability energy, Resources, Abilities & damage, States) with one row per term spelling out From / To names; terms the build provides but nothing uses are shown as "nothing uses it". By piece = each piece's Gives / Gets. Every name is tappable for its quote, conditions and note. Subclass pieces, mods, weapons and armor have info buttons (details sheets / item panel). Picker suggestions (`fitScore`) count links and effects a candidate switches on (Healing Rift turns on Child of the Old Gods' energy).
  - **Damage sources (2026-11-17):** effects may carry `dmg` (what their damage counts as: weapon, grenade, melee, poweredmelee, classability, super, `<el>ability`, weapon types…) and payoffs `from` (accepted sources). Without `dmg` a piece's own kind applies (weapons: weapon + type + element + primary; abilities: slot + element ability + Light/Darkness). Active `counts` rules extend sources (Well of Radiance: weapon → super). A payoff whose providers don't match is listed as "Not active" with the sources it got.
  - **Damage resistance tracker:** `grants damageresistance` effects carry `amt` (PvE %, number must be in the quote), `vs` (all, combatants, players, melee, ranged, explosive, sniper, precision, elements, `subclass`, blocked), `amts` (by copy count, e.g. resist mods 15|25|30), `cat` (counts once), `on` (situational). Glossary terms may carry `dr` (Woven Mail 45%, Frost Armor 31.25% at x5) that applies whenever a piece grants the buff. Totals stack multiplicatively per kind, include all-damage and combatant resistance, split always-on vs "up to" when triggered; ally-only (`who: allies`) is excluded.
  - **Armor mods:** only mods that touch subclasses, abilities, orbs/Armor Charge, stats, healing or resistance are curated (user rule); weapon-handling and plain stat mods are `_skipped` and sink to the bottom of the mod picker as "weapon / stat only".
  - **Set bonuses, artifact, weapon rolls (2026-11-18):** active 2/4-piece set bonuses are pieces (`set:<name>`) shown under Armor; the build holds one artifact (`artA`) and ≤7 perks (`art`: 2 tier-1 slots, 3 tier 1–2, 2 any; `Core.artValid`), curated as `art:<name>` from all 7 Artifact items (`sources.mjs` → `data/interactions/artifacts.json`, bundled as `IX.art`, set on `D.artp`); weapon cards show the whole equipped roll. Glossary `nat` (always-available states, or `"arc"` = Arc grants Amplified) are never "missing"; `from` is the provider's damage source, never the kill type (checker refuses it on buffs/energy). Checked against 47 Mobalytics builds (research only, not shipped).
  - **Sockets (2026-11-18):** `data/sockets.json` (built by `tools/build-api-defs.mjs`, inlined as `window.VS_SOCK`, set on `D.sock`): weapon perk columns per hash (`w` → plug sets `ps` → names `n`) so `Core.sockets` puts CSV perks in Bungie's real columns (API items group by socket index `si`); armor mod sockets per hash (`a` → `lay` [[socketIndex, code]], g general / s slot / t tuning / a artifice / x:raid…, mods for t/a/x in `m`). Build mods are per socket: `b.mods[slot][i]` = mod in socket i of `Core.modLayout` (null empty), the picker lists only that socket's mods, `placeMods` moves stored names into fitting sockets.
  - The old keyword matcher (`synTags`) is kept only for search-style use and its unit tests; it no longer drives the build maker.
- **Stats (Armor 3.0, 2026-11-18):** `Core.armorParts` splits each piece into base roll (DIM base columns, or Bungie's `armor_stats` plugs via `api-defs.as`), masterwork (= current − base − mods on it; Armor 3.0 only on the 3 lowest stats ≤ +5, legacy ≤ +2 all, per Bungie's plug text) and the mods on it by socket. `buildStats` = base + masterwork + tuning + mods (the build's choice per socket, else the one on the piece; never counted twice) + fragments. Archetypes (12) from Bungie plug text (`Core.archetypeOf`); tuning socket only on Tier 5, its mods follow the piece's Tuned stat (+5/−5) or Balanced Tuning (+1 to the 3 lowest). Stat effects per point (`STAT_FX`, 0–200, enhanced above 100) come from the Destiny Data Compendium's Game Mechanics tab.
- **Stat effects + cooldowns (2026-11-19):** `tools/build-stats.mjs` → `data/stats.json` (inlined as `window.VS_STATS`, set on `D.stats`) from Clarity's Character Stats v2 (Edge of Fate; pinned commit, cached in `data/raw/clarity-stats/`; Clarity marks the v2 values as placeholders until tested, and the page says so). Curves are sampled per stat point (0–100 base, 100–200 enhanced); `Core.statAt`, `Core.abilityCooldown` (base cooldown → class / aspect / exotic overrides → stat curve; Supers don't scale) with Data Compendium base cooldowns as fallback (`ddc`). The stats panel shows each stat's lines and, on hover / tap, Clarity's full tooltip filled at your value.
- **Data:** `defs.am[slot] = [[name, energyCost, stats|0, hash]]` (head/arms/chest/legs/class/general from `enhancements.v2_*`); subclass pieces carry `st` (fragment stat bonus/penalty), `fc` (aspect fragment slots) and `c` (plug category); each subclass has `so` (socket index → accepted plug categories). `Core.subList` hides Prismatic's fixed `prism_grenade` from the grenade choices and shows it with Transcendence.

### Clean up (vault-cleaner workflow)
State `CL = {setup, dec, gi, step}` saved to localStorage `vs:clean` and db `config/clean`.
- **Setup:** gear kind; group keys in tick order (weapons: type, frame, element, ammo, slot, rarity, breaker, name; armor: class, slot, archetype, set, tertiary, rarity, name); rank key (weapons: rating/tier/power/season/kills; armor: total/tier/power/season); keep N per group; rules: exotics compared by name only, favorite/keep tags and locked items always kept (they count toward N), skip groups with nothing to trash; optional query filter (any search syntax). Pane menu → "Clean up these results" seeds the filter.
- **Groups:** one group at a time, items ranked, suggestion = keep best N, trash rest. `CL.dec` stores only overrides. Keys: K / T on the hovered tile, ← → between groups.
- **Review & apply:** sets DIM tags (keep, favorites stay favorite / junk) through the normal edit path, so **Export to DIM** sends them; "Copy DIM search: trash" gives an `id:` query for dismantling in DIM.

## Persistence (`src/app.html` → `loadAll` → `loadProfile`)
- **Profiles:** each profile has its own vault, edits (tags/notes), panes, Clean up state, Compare list, builds and personal perk ratings. Game data and the ratings tables are shared. Registry `PROF = {list:[{id, name, color, weapons, armor, updated, sample}], active}` in localStorage `vs:profiles` and db `config/profiles`; the device's last active profile is `vs:activeProfile`.
  - Profile `main` keeps the original paths (no migration). Other profiles prefix them: db `ppath(pid, 'edits/x')` → `p_<pid>_edits/x`, localStorage `pkey(pid, 'vault')` → `vs:p:<pid>:vault`. Always go through `PP(path)` / `PK(key)` for per-profile data.
  - Switching (`switchProfile`) first flushes pending saves (`flushSaves`: panes, Clean up, the edit queue, whose entries carry their full path), then reloads everything for the new profile.
  - **CSV matching:** item instance ids are unique per Bungie account. `noteProfileVault` stores up to 400 ids per profile; `handleFiles` → `profileMatch` compares a new CSV's ids with every profile (≥30% overlap = match) and offers to switch to the matching profile, or to create a new one when nothing matches, instead of overwriting the open profile's vault.
  - Delete (`deleteProfileData`) removes that profile's localStorage keys and db docs; the last profile can't be deleted.
- **As a claude.ai artifact:** `claude.use('db')` is an owner-only document store. Paths (main profile): `meta/vault`, `vault/c0..cN` (≤60 items per doc, docs under 256 KiB), `meta/weaponHashes`, `edits/<itemId>`, `config/panes`, `config/clean`; shared: `ratings/r0..rN` (`{w:{hash:…}}`), `config/profiles`.
- **Opened locally / db unavailable:** localStorage keys `vs:vault`, `vs:edits`, `vs:panes`, `vs:clean`, `vs:compare` (main profile; others `vs:p:<id>:…`), plus shared `vs:ratings`, `vs:profiles`.

## Security (GHOST_PLAN → Security; release blockers)
- **Untrusted input:** everything from DIM CSVs, ratings JSON, the wish list and Aegis's sheet (build time), localStorage/db (incl. personal perk ratings), Clarity, the Compendium and the Bungie API.
  - Item text: always `esc()` in templates. Toasts use `textContent`; the banner builds text nodes.
  - Clarity/Compendium HTML: always `SH(html)` = `Core.sanitizeHtml` (re-serialises; only `div span br`, classes `cl-*`/`dN`, `title` on span). Compendium styles: `Core.sanitizeCss` (color, background-color, font-weight/style, text-decoration only). `test/security.test.js` fails if a `cltx`/`dctx` insert skips `SH()`.
  - CSV import: `Core.LIMITS` (25 MB, 20,000 rows, 600 columns, 20,000-char cells); rows whose `Id` isn't 1–20 digits are dropped. Ratings JSON is coerced in `prepRatings`. Profile ids/colours are validated in `loadRegistry`. Defs icons must be `data:image/…`.
  - No `eval`, `new Function`, string timers, dynamic `<script>`, or inline `on*=` handlers (the strict CSP blocks them anyway).
- **CSV export:** `Core.toCSV(headers, rows)` prefixes `'` to any cell starting with `= + - @` tab/CR (all columns by default). DIM's importer does **not** strip that `'`, so a note starting with one of those characters gains a visible `'` in DIM. Decided 2026-11-15: keep the guard on every column; the export dialog lists the notes that get a `'` so the user can reword them.
- **Hosted CSP** (`build.py --target hosted`): `default-src 'none'`, `script-src` = sha256 of each inline script (hashed over the LF-written file; build output is always written with `\n`), `connect-src 'self' https://www.bungie.net`, `img-src 'self' data: https://www.bungie.net`, `style-src 'self' 'unsafe-inline'` (needed for the many `style="--var:…"` attributes and runtime `<style>` blocks; every value in them is a number, constant, validated hex or `sanitizeCss` output), `font-src 'self' data:`, `manifest-src`/`worker-src 'self'`, `base-uri`/`form-action`/`object-src 'none'`. JSON in the page escapes `</` and `<!--`.
- **Service worker:** caches only this build's listed files (same origin, path in `ASSETS`, no `Authorization` header, `basic` responses); old caches deleted on activate. The page (`./`, `index.html`) is network-first with `cache:'no-cache'` (cache only offline) and install uses `cache:'reload'`: the old stale-while-revalidate worker plus GitHub Pages' `max-age=600` kept phones on old builds (2026-11-16). The app calls `reg.update()` when it returns to the front and offers a tap-to-reload toast on `controllerchange`.
- **Secrets:** the Bungie API key / client_id live only in GitHub Actions secrets (`BUNGIE_API_KEY`, `BUNGIE_CLIENT_ID`) and the gitignored `config/local.json` (`config/local.example.json` shows the shape). Never paste them into chat, commits, logs or issues. `.gitignore` covers `private/`, `*.csv` (except `test/fixtures/`), `config/local.json`, `.env*`, `dist*/`, `data/raw/`.
- **Gates before every commit touching code and every deploy:** `npm run gates`, gitleaks (pre-commit + CI), then a security review of the diff (`/security-review` once `origin` exists; until then a manual checklist pass over GHOST_PLAN's Security section). Report results to the user before deploying.

## Gotchas
- DB snapshot `data()` objects are **frozen**, so build.py wraps them in `structuredClone`. Keep those anchors intact in `app.html`, or update `build.py`.
- Artifact page CSP: inline scripts only (plus cdnjs and similar), no fetch to other hosts, `alert`/`confirm`/`<a download>` blocked. Downloads go through `claude.use('downloads')`, with a copy-text fallback.
- light.gg: be polite. Fetch sequentially with a delay of about 0.9 s, and back off on 429. Server-side fetches from Anthropic's cloud were refused (`client_error`). Fetching from inside a real browser tab on light.gg works.
- Item ids are 19-digit strings. Always treat them as strings, never as Numbers.

## Bungie sign-in (hosted build, 2026-11-16)
- **Actions (2026-11-17, user-approved):** in an item's panel, a Bungie-loaded vault offers **Equip on <class>** (moves from the vault / another character first; replaces what's in the slot), weapon perk options offer **Switch X to Y** (same perk socket, options the weapon has), and armor mods offer **Change this mod** (any mod for that socket's slot). All go through `runActions` (confirm sheet → sequential `BG.act` → local update → `saveVault`). Needs `si`/`h`/`ac`/`roll` on perks and `cid`/`bucket` on items (from `Core.apiToItems`, api-defs plug cats `ah/aa/ac/al/ax/ag` for mod slots) and the account context `bctx` (localStorage: membership type/id + characters). CSV vaults stay read-only.
- Load dialog, phone ⋯ menu: "Sign in with Bungie" → bungie.net authorize → back with `?code&state` → `bungieReturn()` cleans the URL, exchanges the code, `loadFromBungie()` picks the Destiny account (asks if several) and loads the profile through `routeParsed` (same profile matching as CSVs). Tags/notes from the previous vault carry over by item id.
- With a Bungie-loaded vault, dropping DIM CSVs only merges Tag/Notes (`mergeCsvTags`). Export to DIM is unchanged.
- Not from the API (left blank): season, year, source, kill count, crafted level, tuning stat. Armor tertiary = third-highest current stat (approximation).
- Config: `BUNGIE_API_KEY` / `BUNGIE_CLIENT_ID` env (Actions secrets in deploy.yml) or `config/local.json`; without them the button is hidden. Deploy fails if the hosted build isn't configured.
- About & privacy screen (`openAbout`): Bungie notice, credits, storage note, "Delete my data". The Bungie notice still needs the exact wording from bungie.net/7/en/Legal/Terms (Game Content Usage Rules); the page wouldn't render for Claude.
