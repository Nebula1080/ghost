# Curated build interactions

Ghost's build maker shows how pieces of a build work together. Keyword matching can't read conditions
("if running Healing Rift") or things a piece creates (Child of the Old Gods → Void Soul → Briarbinds), so every
piece is **read and curated**: a person or Claude reads its Bungie, Clarity and Data Compendium text and records
what it does as structured data. The build maker only shows curated interactions.

## Files
- `src/*.json`: source packets (generated by `node tools/interactions/sources.mjs`; don't edit). One record per
  piece: `{id, n, kind, el, cls?, hashes, src: {bungie?, clarity?, clarityEnhanced?, compendium?}}`, and for exotic
  weapons/armor `perks: [{n, role, src}]`. `src/glossary-sources.json` holds the Compendium's element and mechanics
  tabs (each element tab starts with a Glossary).
- `glossary.json`: our own compendium of terms. Every `t` used in a piece record must exist here.
- `pieces/<group>.json`: curated records, one file per packet group (same name as `src/<group>.json`).

## glossary.json
```json
{ "terms": {
  "voidsoul": { "l": "Void Soul", "kind": "object", "el": "void", "aka": ["void souls"],
                "def": "A seeking soul summoned from your rift that drains, weakens and suppresses a target.",
                "q": "Cast your rift to create a Void Soul.", "src": "sub:childoftheoldgods" }
} }
```
- id: lowercase letters/digits only, the name without spaces (`voidsoul`, `scorch`, `grenadeenergy`).
- `kind`: `debuff` (on enemies: scorch, weaken, jolt, slow, sever…), `buff` (on you/allies: radiant, amplified,
  devour, woven mail, frost armor, overshield, invisibility…), `object` (things that exist in the world: Void Soul,
  Threadling, Sunspot, Stasis crystal/shard, Firesprite, Ionic Trace, Orb of Power, Tangle, Void Breach…), `energy`
  (grenadeenergy, meleeenergy, classenergy, superenergy), `resource` (armorcharge…), `ability` (grenade, melee,
  classability, super, movement, rift, barricade, dodge, finisher, and named families like `healinggrenade`),
  `damage` (solarweapon, arcdamage… only when a piece really keys off them), `state` (e.g. `transcendence`, `airborne`).
- `isa` (optional): more general terms this one also counts as, e.g. `overshield` (Void Overshield) has
  `"isa": ["overshieldgeneric"]`, so payoffs that accept any overshield link to Void ones too.
- `also` (optional): more Interactions-panel sections the term belongs to, e.g. Orb of Power is a Creation and a
  Resource (`"also": ["resource"]`).
- **Healing yourself vs healing allies:** `healing` (and `cure` / `restoration` as buffs on you) is healing yourself;
  `healallies` is healing other players. A provider that heals "you and allies" records both (`grants healing` and
  `grants healallies`, same quote); one that heals only allies records only `healallies`. A payoff that says "healing
  allies" uses `healallies`; one that says "when you heal" / "while healing" uses `healing`.
- `nat` (optional, `true`): a state any build can enter on its own (airborne, sprinting, sliding, finisher, critical
  health). Payoffs that use it are never listed as missing. A subclass element instead of `true` (`"nat": "arc"`)
  means that subclass grants it intrinsically (Amplified from rapid Arc kills).
- `def`: one or two sentences in our own words. `q`: an exact quote that supports it; `src`: where the quote is
  (a piece id from `src/*.json`, or `compendium:<tab>` for `src/glossary-sources.json`).

## pieces/<group>.json
An array of records, one per piece id in the packet (skip a piece only if it has no gameplay effect, e.g. cosmetics;
list skipped ids in a final `{ "id": "_skipped", "ids": [...] }` record).
```json
{ "id": "sub:childoftheoldgods", "n": "Child of the Old Gods",
  "fx": [
    { "do": "creates", "t": "voidsoul", "on": "when you cast your rift",
      "q": "Cast your rift to create a Void Soul.", "s": "bungie" },
    { "do": "applies", "t": "weaken", "by": "voidsoul", "q": "doing damage and weakening them", "s": "bungie" },
    { "do": "applies", "t": "suppress", "by": "voidsoul", "q": "Combatants affected by the Soul are also briefly suppressed.", "s": "bungie" },
    { "do": "grants", "t": "grenadeenergy", "by": "voidsoul", "if": [{ "slot": "classAbility", "is": ["Healing Rift"] }],
      "q": "you are granted grenade and melee energy (if running Healing Rift)", "s": "bungie" },
    { "do": "grants", "t": "meleeenergy", "by": "voidsoul", "if": [{ "slot": "classAbility", "is": ["Healing Rift"] }],
      "q": "you are granted grenade and melee energy (if running Healing Rift)", "s": "bungie" },
    { "do": "grants", "t": "healing", "by": "voidsoul", "if": [{ "slot": "classAbility", "is": ["Empowering Rift"] }],
      "q": "or health (if running Empowering Rift)", "s": "bungie" },
    { "do": "grants", "t": "classenergy", "on": "defeating a target the Void Soul is draining",
      "q": "Defeating a target who is being drained by your Void Soul grants class ability energy.", "s": "bungie" },
    { "do": "uses", "t": "rift", "q": "Cast your rift to create a Void Soul.", "s": "bungie" },
    { "do": "counts", "t": "voidsoul", "as": "grenade",
      "q": "Void Soul counts as a Grenade Ability and is buffed by, and triggers, grenade-specific effects.", "s": "clarity" }
  ] }
```
For exotic weapons and armor, add `"perk": "<perk name>"` to an effect when it comes from one of the item's perks.

### Effect verbs (`do`)
| do | meaning | links to |
|---|---|---|
| `creates` | spawns an object (Void Soul, Threadling, Sunspot, crystal, Orb of Power) | anything that `uses`/`modifies`/`consumes` it |
| `applies` | puts a debuff on enemies (scorch, jolt, weaken, slow, sever, suspend…) | `uses` it ("damage against scorched targets") |
| `grants` | gives you/allies a buff, energy, resource or healing | `uses` it ("while radiant"), the ability that energy refills |
| `uses` | needs it or pays off on it (trigger or condition) | the `creates`/`applies`/`grants` of the same term |
| `modifies` | changes how something works (Briarbinds → `voidsoul`) | the piece that creates it |
| `consumes` | spends it (e.g. consumes your grenade) | the piece that provides it |
| `counts` | `t` counts as `as` for other effects (Void Soul counts as `grenade`) | anything that uses/modifies `as` |

- `t`: a glossary term id. `by`: the term that does it, when an object does the work (`voidsoul`).
- `on`: short trigger in our words (optional). `who`: `self` / `allies` / `enemies` (optional).
- `if`: conditions that must hold for this effect, all of them. Forms:
  - `{ "slot": "super"|"classAbility"|"movement"|"melee"|"grenade", "is": ["<exact piece name>", …] }`
  - `{ "has": "<term>" }`: the build must provide that term (e.g. an Arc Super for an effect that says "while your Arc Super is active": use slot/is instead when the text names pieces)
  - `{ "weapon": "solar"|"arc"|"void"|"stasis"|"strand"|"kinetic" }`: needs a weapon of that damage type
  - `{ "piece": "<exact subclass piece name>" }`: the build includes that aspect/fragment/ability (e.g. "only with the Vanishing Step aspect")
  - `{ "item": "<exact exotic weapon or armor name>" }`: the build includes that exotic (e.g. Ex Diris with Mothkeeper's Wraps)
  - `{ "subclass": "solar"|"arc"|"void"|"stasis"|"strand"|"prismatic" }`: the build's subclass (e.g. effects that follow your subclass element)
  - `{ "weapon": "super"|"grenade"|"melee" }`: a weapon whose damage type matches that chosen ability's element ("weapon matching your Super's element")
  - `{ "any": [<condition>, <condition>, …] }`: at least one of them (e.g. "Stasis or Kinetic weapon kills")
- `q`: an **exact** quote from the packet text named by `s` (`bungie`, `clarity`, `clarityEnhanced`, `compendium`;
  for exotic weapon/armor perks the source of that perk). Copy it character for character (whitespace may differ).
  Never record an effect that the quote doesn't state. If sources disagree, record what the quote says and put the
  disagreement in `note`.
- `pay` (required on `uses`, `modifies` and `consumes`): what the payoff actually does, in our own words, short
  ("more damage for each different debuff on the target", "grenade energy on kill", "longer Void Soul"). The
  trigger term alone is not enough: a reader must see the effect.
- `pq` (optional): an exact quote that states the payoff, when `q` only names the trigger; checked like `q` (same `s`).
- `note`: optional short interpretation for a person reading the record (e.g. "only Healing Rift; with Empowering Rift
  the soul heals instead").

## Damage sources (`dmg`, `from`)
Destiny decides what a hit "is" (weapon, grenade, melee, class ability, Super) and many payoffs only fire for one
source. Record it:
- `dmg`: on an effect that deals or applies damage, the source terms that damage counts as, e.g.
  `{ "do": "applies", "t": "scorch", "dmg": ["weapon"], … }` when weapon-applied scorch counts as weapon damage, or
  `"dmg": ["grenade"]` for Bleak Watcher ("counts as Stasis Grenade Ability Damage"). Source terms: `weapon`,
  `primaryweapon` / weapon types, `grenade`, `melee`, `poweredmelee`, `classability`, `super`, plus element terms
  (`solarability`, `voidability`…) when the text says so. Without `dmg`, an effect's source is its piece's kind
  (weapons → `weapon`, your grenade → `grenade`…); effects done `by` an object take that object's source.
- `counts` also covers sources: `{ "do": "counts", "t": "weapon", "as": "super", "if": [{ "slot": "super",
  "is": ["Well of Radiance"] }] }` ("Well of Radiance makes all of the caster's Weapon Damage count as Super Ability
  Damage").
- `from`: on a `uses`/`modifies` payoff that only fires for some sources, the accepted source terms, e.g. a perk
  that triggers on "weapon final blows against scorched targets" → `{ "do": "uses", "t": "scorch", "from": ["weapon"] }`.
  Only record `dmg`/`from` when the text (any source) states it. `from` is about the provider's damage source; a
  payoff on a buff or energy ("weapon final blows while you have Devour") never takes `from` (the checker refuses
  it): write the kill type in `pay` / `note`. A payoff on the damage term itself (`uses poweredmelee` with
  `from: ["poweredmelee"]`) links to every piece that provides that term.

## Damage resistance (`amt`, `vs`, `cat`)
On `{ "do": "grants", "t": "damageresistance" }` effects:
- `amt`: the PvE percent as a number (`45` for 45%); the quote must contain that number. Use the PvE value when a
  PvP value follows in brackets ("20% [15%]" → 20) and add a second effect with `"vs": ["players"]` for the PvP value
  when it differs.
- `vs`: what it resists: `all`, `combatants`, `players`, `melee`, `ranged`, `explosive`, `sniper`, `precision`,
  `solar`, `arc`, `void`, `stasis`, `strand`, `kinetic`, `elemental`, `blocked`.
- `amts`: when the amount depends on how many copies are equipped ("15%|25%|30% with 1|2|3 Mods"), the list of totals by copy count; every number must be in the quote. Use with `cat`.
- `vs` may also be `subclass` ("matching your Subclass Element").
- `cat`: optional group id when sources don't stack with each other (only the highest counts), e.g. a mod and its
  copies, or "Empowering"-style exclusive buffs. Everything else stacks multiplicatively.
- `on`: give the trigger ("while Woven Mail is active", "after a powered melee kill") so the tracker can split
  always-on from situational resistance. Stacking buffs: record the per-stack amount and the maximum in `note`.

## Rules
1. Read all sources for the piece before writing. Prefer Bungie for what it does and Clarity/Compendium for details
   that change interactions (counts-as, conditions, exceptions, "does not work with").
2. Record conditions whenever the text has them ("if", "while", "when using", "with X equipped", class/element limits).
3. Record negatives that matter as `note`, not as effects ("does not trigger Ember of X").
4. Use existing glossary terms; add a new term only when nothing fits, in `glossary.json` with `def`, `q`, `src`.
5. `npm test` runs `test/interactions.test.js`: unknown ids or terms, bad verbs, conditions naming unknown pieces, and
   quotes that aren't in the source text all fail.
